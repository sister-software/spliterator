# Spliterator 10

Spliterator 10 makes the conventions Mailwoman wrapped around every call into the library's defaults, and adds a Rust
crate and a Python package that read the same input into the same rows. The engines, sequences, workers and exports
are unchanged.

## Breaking changes

### `normalizeKeys` is off by default

Object rows are keyed by the header as written (after `trim`). Most callers already passed `normalizeKeys: false`.

```ts
// 9.x: { full_name: "Ada" }
// 10:  { "Full Name": "Ada" }
CSVSpliterator.from("Full Name\nAda\n")

// The 9.x keys:
CSVSpliterator.from("Full Name\nAda\n", { normalizeKeys: true })
```

`XLSXSpliterator` follows the same default.

### A repeated header throws in object mode

Without `normalizeKeys`, a header that names a column twice throws `DuplicateHeaderError` (`.column` names it). In 9.x
the later column silently replaced the earlier one. Array and entries rows keep every column, and `normalizeKeys: true`
suffixes repeats (`k`, `k_2`).

### An unterminated quote throws

Input that ends inside a double-quoted region throws `UnterminatedQuoteError` once the rows before it have been
yielded. `.byteOffset` is where the record holding the open quote starts. In 9.x the rest of the input became one
record, and the result read like a shorter file. This applies wherever quote handling is on: CSV and PSV by default,
and any reader given `enableQuoteHandling: true`.

```ts
CSVSpliterator.from('id,name\n1,"open\n2,b\n') // throws UnterminatedQuoteError (byteOffset 8)

// The 9.x reading:
CSVSpliterator.from('id,name\n1,"open\n2,b\n', { allowUnterminatedQuote: true })
```

This replaces Mailwoman's `readUnquotedTSVChecked` and `checkRecordCount`, which counted lines twice to catch the same
short read.

### TSV quote handling is off

The TSV format has no quoting, and a `"` in a tab-separated file is data (GeoNames place names such as
`Ovrag Kyzylak"on`). `TSVSpliterator` now reads it as data. Pass `enableQuoteHandling: true` for a TSV source that
quotes its fields. `CSVSpliterator.EnableQuoteHandling` and `TSVSpliterator.EnableQuoteHandling` hold the class
defaults, read the same way as `ColumnDelimiter`.

This replaces Mailwoman's `readUnquotedTSV` and `readUnquotedTSVText`.

### `drop` and `take` count the rows you receive

For text and JSONL, `drop` and `take` now count rows after blank, empty and comment rows are skipped. In 9.x they
counted earlier, so a whitespace-only row used up a `take`:

```ts
TextSpliterator.from("a\n  \nb\nc", { take: 2 }).toArray()
// 9.x: ["a"]
// 10:  ["a", "b"]
```

`TextSpliterator.count`/`countAsync` count the same way. CSV already counted data rows.

### Whitespace-only JSONL rows are skipped

With `skipEmpty` (the default), a JSONL row of only whitespace is skipped. In 9.x it reached `JSON.parse` and threw. A
parse failure now throws `JSONRowError`, which is still a `SyntaxError` with the same message, and carries `.row`.

### One BOM per record, everywhere

Every path removes one U+FEFF from the start of each record. In 9.x the windowed streaming paths removed one only at the
start of a window, so a `trim: false` or JSONL read could see it mid-stream. `ignoreBOM: true` still keeps them for
`TextSpliterator`.

### Compressed bytes are decompressed

A source that begins with the zstd or gzip magic bytes is decompressed before it is split, including a `Uint8Array`
passed to `from`. Pass `decompress: false` to read the bytes as given. The raw synchronous engine
(`Spliterator.fromSync`) still reads its bytes as given.

## New behaviour

### Transparent decompression

Paths, streams and in-memory bytes are decompressed by magic bytes, whatever their names. Concatenated zstd frames and
gzip members are read through. In Node both formats work; in a browser gzip goes through `DecompressionStream` and
zstd throws a `TypeError` rather than parsing compressed bytes. A compressed path can be read twice: the library
reopens it for each read.

A compressed source cannot be segmented: `AsyncSpliterator.segments`, `asMany` and `asManyWorkers` throw a `TypeError`.

### Compressed siblings

A path `p` reads `p.zst`, or failing that `p.gz`, when one exists, so a corpus compressed one part at a time reads the
same before and after. Pass `preferCompressed: false` to read `p` itself. Segmenting never redirects.

### Migrating Mailwoman's helpers

| Mailwoman                                       | Spliterator 10                                                               |
| ----------------------------------------------- | ---------------------------------------------------------------------------- |
| `delimitedSource(await preferCompressed(path))` | `path`                                                                       |
| `readUnquotedTSV(path)`                         | `TSVSpliterator.fromAsync(path, { header: false })`                          |
| `readUnquotedTSVChecked(path)`                  | the same; an open quote can no longer shorten a TSV read, and throws in CSV  |
| `checkRecordCount(file, text, records)`         | not needed; an unterminated quote throws                                     |
| `headerColumnIndex(file, header)`               | object mode throws `DuplicateHeaderError`                                    |
| `normalizeKeys: false`                          | the default                                                                  |
| `read_jsonl` in `data/delimited.py`             | `spliterator.read_jsonl(path)`                                               |
| `csv.DictReader`                                | `spliterator.read_csv(path)`; note `trim` is on and missing columns are `""` |

## Semantics

Every binding implements this table, and the conformance suite in `conformance/` tests it in all three languages.

### Sources

| Topic          | Rule                                                                                                                                            |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Decompression  | `decompress` (default on): a source beginning with `28 B5 2F FD` (zstd) or `1F 8B` (gzip) is decompressed. Frames and members are concatenated. |
| Sibling lookup | `preferCompressed` (default on): a path `p` not ending in `.zst`/`.gz` reads `p.zst`, else `p.gz`, else `p`.                                    |
| Offsets        | Error offsets are bytes of the decompressed input.                                                                                              |

### Records

| Topic              | Rule                                                                                                                                              |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Delimiter          | Default `\n`. Any non-empty byte string; with quote handling it may not contain `"`.                                                              |
| Quote handling     | Each `"` toggles a quoted region in which a delimiter does not split. Records keep their quotes. On for CSV and PSV, off for text, JSONL and TSV. |
| CRLF               | `crlf`: one `\r` directly before a delimiter belongs to it. A `\r` at the end of input is data. On for CSV/TSV/PSV.                               |
| Tail               | The bytes after the last delimiter are a record, even when empty (`String.prototype.split`).                                                      |
| Empty records      | `skipEmpty` (default on) drops records whose bytes are empty after CRLF removal. `""`, `,,` and a BOM-only record are not empty.                  |
| Unterminated quote | Throws `UnterminatedQuoteError` (`byteOffset`) after the records before it, unless `allowUnterminatedQuote`. An early stop never throws.          |

### Text rows

| Topic           | Rule                                                                                                                                                                                    |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decoding        | UTF-8, lossy: each maximal invalid subsequence becomes U+FFFD.                                                                                                                          |
| BOM             | One U+FEFF at the start of each record is removed.                                                                                                                                      |
| Trim            | `trim` (default on) removes ECMAScript whitespace: U+0009–U+000D, U+0020, U+00A0, U+1680, U+2000–U+200A, U+2028, U+2029, U+202F, U+205F, U+3000, U+FEFF. Not U+0085, not U+001C–U+001F. |
| Blank rows      | With `trim` and `skipEmpty`, a row that trims to nothing is dropped.                                                                                                                    |
| `drop` / `take` | Count rows yielded.                                                                                                                                                                     |

### JSONL rows

| Topic          | Rule                                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Rows           | Decoded as text rows without trimming; whitespace-only rows skipped with `skipEmpty`.                                                |
| Comments       | `comment` prefixes skip rows whose first text after spaces, tabs, CRs and LFs starts with a prefix, and whitespace-only rows.        |
| Numbers        | Each language's native parser. Integers beyond ±2^53 are exact in Python and Rust, rounded in TypeScript. Strings are never coerced. |
| Non-standard   | `NaN`, `Infinity` and trailing commas are rejected everywhere.                                                                       |
| Duplicate keys | The last value wins.                                                                                                                 |
| Errors         | `JSONRowError` with `row`, the index among rows that reached the parser (after skipping and `drop`).                                 |

### CSV, TSV and PSV rows

| Topic             | Rule                                                                                                                                                                                                                  |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Columns           | A record is decoded, its BOM removed, and split on the column delimiter, honouring quotes. Empty cells are kept.                                                                                                      |
| Unquoting         | A cell of two or more characters that starts and ends with `"` loses them; `""` inside becomes `"` when the cell holds a doubled quote. Other quotes are literal.                                                     |
| Trim              | `trim` (default on) runs after unquoting, header included. A trimmed cell that then starts with `"` is unquoted and trimmed once more. A cell whose first and last characters are both printable ASCII is left as is. |
| Header            | `header` (default on) takes the first non-empty record. `normalizeKeys` (default off) snake-cases and suffixes repeats.                                                                                               |
| Duplicate headers | Object mode without `normalizeKeys` throws `DuplicateHeaderError`.                                                                                                                                                    |
| Modes             | `object` (default with a header), `array` (default without), `entries` (`[key, value, index]`).                                                                                                                       |
| Short rows        | Missing columns are `""` in object and entries rows; array rows stay short.                                                                                                                                           |
| Long rows         | Cells past the header are keyed `column_<index>`.                                                                                                                                                                     |
| `drop` / `take`   | Count data rows.                                                                                                                                                                                                      |
| Transformers      | TypeScript and Python: by header name, after trim, object and entries modes. Not in Rust.                                                                                                                             |

### Known differences

- **Large integers.** TypeScript's `JSON.parse` rounds integers beyond ±2^53; Python and Rust keep them exact.
- **Decoding errors.** TypeScript's `fatal: true` (throw on invalid UTF-8) has no counterpart; Rust and Python always
  decode lossily.
- **Non-UTF-8 column delimiters** (a lone `0xFF`). TypeScript's byte fallback removes a BOM from the start of every cell
  rather than every record.

## Rust and Python

The Rust crate (`spliterator` on crates.io, `crates/spliterator`) and the Python package (`sister-software-spliterator` on PyPI, `crates/spliterator-py`, imported as `spliterator`) share
the semantics above. The Python package is a thin layer over the crate: rows cross into Python in batches read with the
interpreter released, and JSON is parsed by Python's own decoder so values are native.

```rust
for row in spliterator::csv::Reader::open("people.csv", spliterator::csv::Options::csv())? {
    println!("{:?}", row?.get("Full Name"));
}
```

```python
import spliterator

for row in spliterator.read_csv("people.csv"):
    print(row["Full Name"])
```

Option names are the TypeScript names, in snake_case for Rust and Python. Neither port offers XLSX, workers, sequences
or `columnScan`; the Rust port has no transformers.
